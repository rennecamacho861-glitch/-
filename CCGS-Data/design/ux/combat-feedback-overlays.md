# UX Spec: 照面反馈弹窗

> **Status**: Ready for Implementation  
> **Author**: Codex + UX Design  
> **Last Updated**: 2026-05-11  
> **Template**: Lightweight HUD/Overlay Spec

## Purpose & Player Need

玩家在黑暗迷宫中遇敌和进行战斗回合时，需要立刻知道“发生了什么、谁占优、自己为什么受伤或拿到窗口”。反馈弹窗负责把关键结算从右侧日志中提出来，形成短促照面演出，但不暂停战斗节奏。

## Information Architecture

必须弹出：

- 遇敌：敌人名、照面状态、视野优势归属。
- 战斗回合：玩家动作、敌人动作、伤害/闪避/防御/重伤/优势窗口中的主要结果。
- 关键危险：枪击、重伤、敌方优势、脱战或击败。

仍留在普通日志即可：

- 道具描述长文本。
- 低优先级移动记录。
- 多条情报的完整列表。

## Layout & Behavior

- 弹窗位于 playfield 中央偏下，宽度约 360-520px。
- 桌面端不得覆盖底部战斗按钮；移动端位于战斗面板上方或上半屏安全区域。
- 默认显示 0.9-1.2 秒，自动淡出。
- 不要求玩家确认，不吞掉键盘移动或战斗按钮输入。
- 若短时间内多个事件到达，只显示最新事件；完整历史仍在日志和战斗记录中。

## Tone Mapping

| Tone | 用途 | 视觉 |
|---|---|---|
| `danger` | 敌方优势、受击、枪击、重伤 | 红边、暗红闪 |
| `advantage` | 我方优势、成功闪避、防御读出窗口 | 金边、暖光 |
| `neutral` | 正常照面、僵持、无明显收益 | 冷灰边、低亮 |
| `intel` | 获得情报 | 琥珀细边、短亮 |

## Data Requirements

| Data | Source System | Read / Write | Notes |
|---|---|---|---|
| `feedbackEvents` | `src/sim` | Read | HUD 只读，不清空模拟状态 |
| `EncounterState.log` | `src/sim` | Read | 回合弹窗正文应与最新回合日志一致 |
| `AdvantageState` | `src/sim` | Read | 决定弹窗 tone 与标题 |
| `GameState.map.visible` | `src/sim` | Read | 视野压缩后 HUD/渲染共同使用 |

## Accessibility

- 文本必须能独立表达结果，颜色只做辅助。
- 弹窗动画必须支持 `prefers-reduced-motion: reduce`。
- 弹窗出现期间不能阻断键盘或鼠标输入。
- 弹窗文字不超过 2 行主要信息，避免在移动端溢出。

## Acceptance Criteria

## v0.8.6 追加：敌人逃跑、击杀与说服弹窗

本追加覆盖三个高优先级结果反馈：

- `enemy-flee`：敌人利用优势窗口后撤并脱战时弹出。标题固定为“敌人逃跑”，正文写敌人姓名和脱战结果。
- `enemy-defeated`：玩家击杀敌人时弹出。标题固定为“敌人击杀”，正文写敌人姓名和即将回收装备。
- `persuasion-intel`：玩家说服成功时弹出。标题固定为“说服成功”，正文只列出本次新增的结构化情报；允许字段仍然只有 `属性 = 数值`、`拥有/未见道具`，不加入路线、意图或态势描述。

HUD 必须按事件队列逐条显示确认式弹窗。若同一结算帧同时产生“击杀”和“掉落”，玩家确认击杀弹窗后继续看到掉落弹窗，不能只显示最后一条事件。

- [ ] 触发遇敌时出现“照面”弹窗，显示敌人名和优势归属。
- [ ] 每个玩家战斗动作结算后出现一次回合结果弹窗，正文包含最新回合主要结果。
- [ ] 弹窗 0.9-1.2 秒自动淡出，不需要点击确认。
- [ ] 弹窗不遮挡战斗动作按钮和拾取三选一按钮。
- [ ] 开启 reduced motion 时无 camera shake，仍保留文字反馈。
- [ ] 玩家默认精神 3 时明亮视野半径为 1，Phaser 视野圈与实际可见格一致。
