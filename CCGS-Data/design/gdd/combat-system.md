# 《照面之时》Combat System GDD

版本：v0.8.17 战斗博弈与脚本化教学补充
状态：Confirmed  
日期：2026-05-21
规则真源：本文件负责照面战斗、视野领先、情报读牌、优势资源、逃跑/说服、战斗 AI 接口与战斗验收；`rulebook.md` 保留总规则摘要。

## 1. Overview

照面战斗是《照面之时》的核心体验：单位在黑暗迷宫中突然互相进入可见或察觉状态，随后用 2-4 个动作回合完成读牌、下注、反制和离场。

战斗不追求传统 HP 消耗战。系统应让玩家快速理解：

- 我为什么先手或吃亏。
- 我已经知道了对方什么。
- 下一手进攻、防御、左闪、右闪、逃跑或说服分别承担什么风险。
- 我什么时候应该继续压、什么时候应该离桌。

本修订优先修复三类体验问题：

- 攻击同时推进伤害、重伤、状态、被动链和软收束，导致“攻击就完事”。
- 防御和躲闪产生的信息没有稳定转化为下一手决策。
- 道具与 AI 成长放大后期滚雪球，而基础动作博弈被稀释。

## 2. Player Fantasy

玩家不是在打长血条，而是在黑暗里和另一个拾荒者赌命。

理想的一次照面：

1. 玩家先听见或看见一点线索。
2. 玩家通过视野领先、防御或躲闪获得可行动情报。
3. 玩家用这条情报选择进攻、防御、左闪、右闪、逃跑或说服。
4. 第 2-3 手开始出现明确出口：击败、重伤、优势资源、逃跑、说服或双方后退脱战。

输了也必须能复盘：“我没看到对方”“我没读出攻击方向”“我贪了攻击”“我让对方的构筑启动了”。

v0.8.17 起，首次选择新手教程的玩家必须先经历一段脚本化训练照面。训练照面不替代正式规则；它用固定敌人和固定动作让玩家实际体验“先防御读情报，再用方向闪避拿优势，最后把优势兑现为先手击杀或说服”的完整链条。

## 3. Design Pillars

| Pillar | Rule Test |
|---|---|
| 视野领先是读牌权，不只是伤害先手 | 先看见敌人的一方必须得到结构化情报或开局选择权；速度 +2 不能是唯一收益 |
| 基础动作先成立，道具只做小幅改写 | Attack / Defense / Dodge 必须各有赢面和反制面；道具不得替代基础动作 |
| 防御和躲闪要产出下一手决策 | 有效防御和成功躲闪必须给玩家可用信息，不只是拖延 |
| 战斗必须快速找出口 | 第 3 回合起进入软收束；允许第 4-5 回合，但每回合必须推动状态变化 |
| AI 可解释，不作弊 | AI 只能用可见、已知、推测或自身状态决策，不读取玩家隐藏真值 |

## 4. Core State

### 4.1 EncounterState

`EncounterState` 至少需要表达：

- 当前敌人 ID。
- 当前动作回合数。
- 当前阶段：`chooseAction` / `advantageWindow` / `resolved`；v0.8.16 起玩家不再被优势窗口强制暂停，`advantageWindow` 仅保留兼容旧接口。
- 当前优势：最新归属、来源、双方可支付优势点数。
- 双方已出动作记录。
- 双方攻击方向序列索引。
- 当前战斗 active effects。
- 本场战斗日志和反馈事件。

### 4.2 AdvantageState

优势不是永久 buff，也不再只是一瞬间短窗口。v0.8.16 起，优势是可积累、可支付的照面资源。

优势来源：

- 视野领先。
- 重伤。
- 有效防御。
- 成功躲闪。
- 道具。
- 第 3 回合后的软收束。

每次获得优势时，对应单位获得 1 点优势资源。玩家拥有至少 1 点优势时，可在照面内任意可操作时机支付：

- 逃跑：支付 1 点优势，成功后脱战，失败后敌人获得追击修正。
- 说服：支付 1 点优势，按说服公式结算合作/停战。
- 继续战斗：支付 1 点优势，选择 `pressPower` 或 `pressTempo`，下一动作回合近战伤害 +1 或速度 +1；多点优势可分次支付并叠加。
- 优势道具：原“优势窗口使用”道具改为支付 1 点优势使用。

## 5. Combat Entry And Vision

进入照面前必须先判断双方可见状态。

| 状态 | 规则 |
|---|---|
| 双方互相看见 | 直接进入正常照面 |
| A 看见 B，B 未看见 A | A 获得视野领先 |
| A 只察觉 B | 不获得完整先手，但可获得低价值提示 |
| 双方都未见且未察觉 | 不进入战斗 |

视野领先效果：

- 获得 1 点开局优势资源。
- 获得一次视野来源情报；优先给对当前第一手有用的属性或道具。
- 第一次近战进攻速度 +2。
- 若有远程手段且视野、距离、射线合法，可以在正式面板前进行一次远程先手。

限制：

- 同一对单位的一次遭遇中，未见远程先手最多 1 次。
- 远程先手后，受击方至少进入察觉状态，并获得方向、红光或枪声提示。
- 视野领先不得直接生成 AI 意图、路线或性格文本。

## 6. Intel And Reads

战斗内单体情报只允许三类：

| 类型 | 示例 | 用途 |
|---|---|---|
| `statExact` | `速度 = 5` | 判断先后手、躲闪、逃跑、重伤 |
| `itemExact` | `拥有左轮，剩余 2 发` | 判断是否防枪、诱导消耗、规避道具 |
| `attackDirection` | `下次攻击方向 = 左` | 帮助选择左闪或右闪 |

禁止把以下内容写入情报列表：

- 敌人意图。
- 敌人路线。
- 敌人性格。
- “偏进攻”“想逃跑”“擅长续战”等态势文本。

### 6.1 情报预算

`intelBudget = 智力 + 来源修正 + 道具修正 + 优势修正 - 干扰惩罚`

| intelBudget | 情报点 |
|---:|---:|
| 0-2 | 0 |
| 3-4 | 1 |
| 5-6 | 2 |
| 7-8 | 3 |
| 9+ | 4 |

### 6.2 来源修正

| 来源 | 修正 | 输出限制 |
|---|---:|---|
| 首次看见敌人 | +1 | 数值或道具推测 |
| 视野领先进入战斗 | +2 | 具体属性或具体道具 |
| 有效防御 | +3 | 优先揭示攻击者属性、道具或下一击方向 |
| 成功躲闪 | 直接 1 点，且 +2 | 至少 1 条；可揭示下一击方向 |
| 躲闪但未被攻击 | +0 | 最多 1 点低价值属性或道具推测 |
| 对方使用道具 | +3 | 揭示该道具；计数珠可揭示剩余次数 |
| 陷阱/报警触发 | 直接 1 条 | 属性或道具；位置提示不进入情报列表 |
| 说服成功 | 直接 1-2 条 | 属性或道具 |

## 7. Base Actions

玩家基础动作为：

- `Attack` 进攻。
- `Defense` 防御。
- `DodgeLeft` 左躲闪。
- `DodgeRight` 右躲闪。

远程、治疗、投掷、布置、压制、状态、缴械等动作必须来自道具。

### 7.1 Attack

进攻负责兑现优势，而不是无脑最优。

规则：

- 近战进攻需要相邻或道具定义的近战范围。
- 双方都进攻时，速度高者先结算。
- 同速时，力量高者先结算。
- 速度和力量都相同，则双方同时结算。
- 先击中并造成重伤时，慢速方本回合攻击被打断。
- 先击中但未造成重伤时，慢速方仍会完成攻击。

攻击风险：

- 打进防御会被大幅减伤，并可能让防御者获得有效防御。
- 打进正确躲闪会落空，并让躲闪者获得优势和情报。
- 未掌握速度、方向、道具信息时，攻击是下注，不是默认答案。

### 7.2 Defense

防御负责减伤、读牌和稳定局势。

防御效果：

- 受到近战或远程攻击时，最终伤害按防御减伤结算，默认只承受 40%。
- 防御时重伤阈值额外 +2，仅用于本次受击判定。
- 若防御者承受了敌方攻击或真实压制动作，并满足有效防御条件，则获得情报和优势候选。

有效防御条件：

- 本回合确实承受敌方攻击、远程、投掷或压制动作；且
- 防御至少减少 2 点伤害，或防止一次重伤，或触发防御型道具/情报效果。

若敌人没有攻击或压制，防御只可获得低价值情报，不直接获得优势。

### 7.3 Dodge

躲闪负责读方向和反制攻击。

规则：

- 玩家必须选择左闪或右闪。
- 攻击者每次真实攻击消耗下一条 `attackDirection = left | right`。
- 选择方向与攻击方向一致时，使用正确方向躲闪率。
- 方向错误时，使用错误方向躲闪率。
- 成功躲闪获得优势候选和至少 1 条情报。
- 躲闪但未被攻击时，不获得优势；最多获得 1 次低价值情报。

正确方向躲闪是高胜率反制；无方向情报时，躲闪是明确的押注。

## 8. Action Matrix

| 玩家动作 | 敌人动作 | 主要结果 | 博弈含义 |
|---|---|---|---|
| Attack | Attack | 速度先手，同速力量破平；未重伤则慢速方反击 | 双方都押伤害 |
| Attack | Defense | 玩家伤害被减免；敌人若有效防御则获得情报/优势候选 | 进攻被读牌克制 |
| Attack | Dodge 正确 | 玩家攻击落空，敌人获优势候选 | 进攻被读向克制 |
| Attack | Dodge 错误 | 玩家命中，敌人承担正常或部分修正伤害 | 读错方向付代价 |
| Defense | Attack | 玩家减伤；若有效防御则获得情报/优势候选 | 防御赢莽攻 |
| Defense | Defense | 双方低价值读牌；不直接给优势 | 双方谨慎，推动软收束 |
| Defense | Dodge | 双方无硬结果；各自只可能获得低价值信息 | 空转，不奖励优势 |
| Dodge 正确 | Attack | 玩家闪开，获得优势候选和情报 | 信息兑现 |
| Dodge 错误 | Attack | 玩家受击 | 错读方向 |
| Dodge | Defense | 玩家未被攻击，不获优势 | 躲闪被防御拖掉 |
| Ranged | Defense | 左轮不被防御减免；仅木盾片等明确远程减伤道具可抵消 | 枪线是稀有强压迫，靠视野/墙/躲闪反制 |
| Ranged | Dodge 正确 | 远程落空，躲闪者获优势候选 | 方向情报克制枪线 |

## 9. Formulas

| 名称 | 公式 | 说明 |
|---|---|---|
| 最大生命 | `6 + 体质 x 2` | MVP 属性范围 1-6 |
| 基础近战伤害 | `2 + floor(力量 / 2) + 武器修正` | 道具修正进入同族上限 |
| 重伤阈值 | `5 + floor(体质 / 2) + 防御重伤修正` | 防御重伤修正默认 +2 |
| 防御减伤 | `ceil(原伤害 x 0.4)` | 即默认减免约 60% |
| 正确方向躲闪率 | `75% + 速度差 x 8% + 道具修正` | 下限 55%，上限 95% |
| 错误方向躲闪率 | `10% + 速度差 x 3% + 道具修正` | 下限 5%，上限 30% |
| 逃跑成功率 | `55% + clamp(速度差, -3, 3) x 8% + 道具修正` | 下限 25%，上限 90% |
| 说服值 | `智力 + min(相关有效情报, 3) + min(支付修正, 2) + min(道具修正, 2) + 局势修正 - 敌意修正` | 普通目标值默认 8 |
| 高伤触发 | `finalDamageAfterMitigation >= 6` | 每次攻击最多触发 1 个 highDamage 事件 |

## 10. Advantage Resource

优势资源出现后，拥有者不必立即兑现；玩家可以继续动作，也可以在任意可操作时机支付优势。

玩家优势支付：

| 选择 | 规则 |
|---|---|
| 逃跑 | 支付 1 点优势；成功后拉开 1 格并脱战；失败后敌人获得追击修正 |
| 说服 | 支付 1 点优势；按说服值与目标值判定；可支付战利或道具增加修正 |
| 继续战斗：力量 | 支付 1 点优势；下一动作回合近战伤害 +1，可叠加 |
| 继续战斗：节奏 | 支付 1 点优势；下一动作回合速度 +1，可叠加 |

限制：

- 没有优势时，上述选项禁用。
- 同一优势点只能支付一次。
- 同场照面可累计多点优势并分次支付。
- 每次选择继续战斗必须生成确认式反馈，说明下一动作回合获得的临时加成。

## 11. Closure

每个动作回合结束都先检查硬结果：

1. 生命归零。
2. 重伤造成者获得 1 点优势资源。
3. 已有优势资源者可以在之后任意可操作时机支付优势。

从第 3 个动作回合结束开始，若没有硬结果，执行软收束：

1. 有效防御者获得 1 点优势资源。
2. 成功躲闪者获得 1 点优势资源。
3. 造成未被有效防御压低的显著伤害者获得 1 点优势资源。
4. 当前生命更高者获得 1 点优势资源。
5. 速度更高者获得 1 点优势资源。
6. 仍无法区分时双方各后退 1 格并脱战。

第 3 回合不是硬上限，而是开始强制找出口。战斗可以进入第 4-5 回合，但每回合都必须推动伤害、情报、优势、逃跑、说服或脱战。

## 12. Item Constraints In Combat

道具服务基础动作，不替代基础动作。

全局限制：

- 每个战斗回合每名单位最多主动使用 1 件道具。
- 同类数值修正同轮只取最高。
- 每件被动每回合最多触发 1 次。
- 自动触发链每战斗回合全场最多 5 次。
- 同名被动不叠加。
- 高伤、重伤、状态、暴击等事件每次攻击最多各触发一次对应同族收益。

建议新增有效构筑预算：

- 玩家主动槽：4。
- 玩家被动预算：5。
- common 被动占 1，uncommon 占 2，rare 占 3。
- 未装入预算的被动不触发，可作为战利、支付物或待替换物保留。

## 13. Enemy AI Interface

AI 不需要真实理解道具连携，但必须有可解释的构筑倾向。

推荐抽象：

1. `ItemCapability`：从道具 tags、ports、effects、被动规则中归一化能力。
2. `TacticalPackage`：把能力组合成战术包，例如 `BurnCrit`、`PoisonTempo`、`DodgeCounter`、`GuardIntel`、`AdvantagePress`、`RangedReload`、`RecoverEscape`、`LootHunter`。
3. `Intent`：AI 内部计划字段，只影响权重，不进入玩家情报。
4. `ScoreBreakdown`：记录动作、拾取和丢弃评分来源，便于测试。

AI 禁止：

- 读取玩家隐藏属性真值。
- 读取玩家隐藏道具真值。
- 把内部意图写入玩家情报。
- 为了追赶玩家无提示地膨胀属性。

AI 可以使用：

- 自身属性、生命、状态、道具、优势。
- 当前可见和察觉信息。
- 已获得的结构化情报。
- 可从真实地图事件推导的提示，如枪声、红光、被翻空节点。

## 14. Exploration Interface

战斗系统依赖探索提供可下注的前置信息。

地图应形成三类路线：

| 路线 | 承诺 | 风险 |
|---|---|---|
| 安全线 | 较短、敌人少、低价值资源 | 构筑慢，战利低 |
| 资源线 | 绕路 6-12 回合，更多拾取点 | 可能错过撤离节奏 |
| 热点线 | 靠近空投、内战、高价值节点 | 敌人争夺、毒圈和远程风险 |

每局至少 3 个主要决策路口。每个路口应提供 1-2 个真实但不完整的提示，例如红光、枪声、翻空节点、回声区、污染边缘或空投方向。

暂缓把“探步”加入正式动作。只有在路线三角成立后，才评估是否加入消耗 1 回合换局部视野的探步。

## 15. Scripted Tutorial Combat

脚本化教学照面只在玩家选择“需要新手教程”后进入，属于正式局前的训练场景。它必须使用正式战斗公式结算，但允许固定敌人、固定动作、固定攻击方向、输入门控和教程检查点恢复。

### 15.1 Tutorial Scenario Entry

- 教程场景在正式开局四选一之前运行。
- 教程场景生成 2 名教学敌人，均位于玩家 5 格内，属性总值为 10。
- 教学敌人不走普通 AI 权重，不参与普通拾取成长、敌人内战、掉落、空投、毒圈或撤离收益。
- 教程偏好和已读弹窗由 HUD/localStorage 保存；教学步骤、脚本敌人和输入允许列表由模拟层保存。
- 任意步骤都必须允许玩家跳过教程。跳过后清空教程场景并进入正式开局四选一。

### 15.2 Tutorial Enemy 1: Defense, Intel, Dodge, Advantage, Kill

第一名教学敌人用于建立“先读再打”的战斗心智。

建议属性：精神 1、智力 1、力量 5、速度 2、体质 1。若按现有公式无法稳定演示无防护高伤/重伤，可给其不掉落的教学长刀或把教学敌人属性总值改为 12；不得用 HUD 假造结算结果。

固定脚本：

1. 敌人连续进攻，攻击方向序列为左、右、左。
2. 第一手引导玩家防御。有效防御后，玩家获得 1 点优势和至少 2 条情报；优先暴露 `体质 = 1` 与速度/攻击相关情报。
3. 如果玩家在读出方向前选择攻击，使用正式结算演示敌人先手和重伤风险，然后通过教程检查点恢复到上一教学步骤。
4. 第二次防御后，优先给予 `attackDirection` 确认情报。
5. 下一手引导玩家按情报选择正确方向躲闪。正确躲闪必定成功，并额外使玩家获得 2 点优势。
6. 玩家累计 3 点优势后，引导玩家连续支付 3 点优势选择 `pressTempo`，把下一动作回合速度修正叠到 +3。
7. 最后引导玩家进攻，凭速度修正先手重伤敌人，并用后续进攻完成击杀。

### 15.3 Tutorial Enemy 2: Persuasion Exit

第二名教学敌人用于建立“说服也是出口”的心智。

建议属性：精神 2、智力 1、力量 2、速度 2、体质 3。敌人固定低压动作，不携带会改变教学结论的道具。

固定脚本：

1. 第一手引导玩家防御或按已知方向躲闪，获得 1 点优势。
2. 情报优先暴露 `智力 = 1`。
3. 弹窗说明说服值受玩家智力、有效情报、支付修正、道具修正和局势影响；低智力敌人更适合说服。
4. 高亮“说服”。玩家支付 1 点优势后，说服成功，敌人进入停战/合作状态。
5. 教程总结后进入正式开局四选一。

### 15.4 Tutorial Safety Rules

- 教程演示中受到的伤害、重伤、状态和临时修正不得带入正式开局。
- 教学敌人不掉落正式道具。
- 教程检查点恢复只允许用于训练场景；正式局不得使用。
- 所有教学弹窗必须解释刚发生的真实机制，不允许只写“按这里”。

## 16. Item Text Policy

玩家主文案必须说明“拿到后能做什么”，不能显示生产字段。

推荐字段：

- `uiShort`：拾取卡、背包、日志用，一句话说明收益。
- `uiLimit`：限制、代价、次数、推进回合。
- `uiEnemyCounter`：只在已知敌方道具详情中显示，写成玩家可执行应对。
- `rulesDescription`：规则核验字段，不直接显示给玩家。
- `devNotes`：端口、动画、实现校验，不进 UI。

禁止在玩家主文案中出现：

- 端口名、trigger、effectKey。
- 动画事件、DOM、Phaser、代码实现。
- “反制：”作为通用字段。
- 未实现的风险或收益。
- 泛泛“获得情报”但不说明目标和输出类型。

示例：

- 回声针：`战斗外使用：标出最近敌人或拾荒点所在的 2x2 回响区；不显示具体格。`
- 药膏铁盒：`战斗或场外使用：你回复 1 点生命。场外使用会推进 1 回合；每回合同一件最多使用一次。`
- 防御镜片：`防御成功后：获得当前敌人的 1 条属性或道具情报。`

## 18. Edge Cases

- 同速同力量互攻：双方同时结算伤害；若双方同时生命归零，玩家本局失败，敌人也被击败。
- 防御无人攻击：不触发有效防御；最多获得低价值情报。
- 躲闪无人攻击：不触发优势；最多获得低价值情报。
- 远程被防御：防御减免远程，但不提供额外掩体，除非道具说明。
- 远程被正确躲闪：远程落空，躲闪者获得优势候选。
- 攻击方向情报过期：攻击者消耗对应攻击方向后，该情报必须过期。
- 玩家未知来源受伤：必须生成方向、红光或枪声提示。
- 说服失败支付道具：单次最多支付 2 件；支付效果必须写入日志。
- AI 内战：使用同一套伤害、重伤、优势、道具和消耗规则，但可以自动收束。

## 19. Tuning Knobs

| 参数 | 默认 | 建议范围 | 调整目的 |
|---|---:|---:|---|
| 防御减伤 | 60% | 50%-70% | 防御是否值得试探 |
| 防御重伤修正 | +2 | +1 到 +3 | 防御能否防止一击重伤 |
| 正确方向躲闪基础率 | 75% | 65%-85% | 读向收益 |
| 错误方向躲闪基础率 | 10% | 5%-20% | 盲闪风险 |
| 逃跑基础率 | 55% | 45%-65% | 离场可靠性 |
| 逃跑上限 | 90% | 85%-95% | 防止速度滚雪球 |
| 普通说服目标值 | 8 | 7-9 | 合作难度 |
| 高伤触发阈值 | 6 | 5-7 | 防止高伤被动过频 |
| 玩家主动槽 | 4 | 3-5 | 主动构筑容量 |
| 玩家被动预算 | 5 | 4-7 | 被动滚雪球控制 |
| 战斗触发链上限 | 5 | 4-6 | 防止被动递归爆炸 |

## 20. Acceptance Criteria

### Combat

- AC-CMB-001：一次照面进入前必须先计算双方可见/察觉状态，并记录视野领先归属。
- AC-CMB-002：视野领先至少提供开局优势和一次可追溯结构化情报机会；不能只给速度 +2。
- AC-CMB-003：基础动作必须包含进攻、防御、左躲闪、右躲闪；远程、治疗、压制等动作必须来自道具。
- AC-CMB-004：进攻打防御时，防御必须减伤并可触发有效防御；攻击方不得因为小额伤害自动压过有效防御。
- AC-CMB-005：正确方向躲闪与错误方向躲闪使用不同公式；成功躲闪必须获得至少 1 条可追溯情报。
- AC-CMB-006：第 3 动作回合起执行软收束，优先级为有效防御、成功躲闪、显著伤害、生命、速度、双方后退脱战。
- AC-CMB-007：续战每次支付 1 点优势，只能选择力量或节奏之一；同场照面可通过再次获得或积累优势重复选择，同类加成可叠加到下一动作回合。
- AC-CMB-008：每次选择继续战斗必须生成确认式反馈弹窗，明确说明下一动作回合近战伤害 +1 或速度 +1。

### Intel

- AC-CMB-020：战斗内单体情报只允许属性数值、具体道具、下一次攻击方向。
- AC-CMB-021：攻击方向情报必须读取模拟层真实下一击方向，并在该攻击被消耗后过期。
- AC-CMB-022：玩家未知来源受伤时必须获得来源提示，不允许无解释扣血。

### Economy And Items

- AC-CMB-040：每个战斗回合每名单位最多主动使用 1 件道具。
- AC-CMB-041：同类数值修正同轮只取最高；同名被动不叠加。
- AC-CMB-042：每战斗回合全场自动触发链最多 5 次，达到上限后写入日志。
- AC-CMB-043：玩家可同时触发的被动必须受有效构筑预算限制；未装备被动不得触发。
- AC-CMB-044：rare 主动道具必须逐件显式声明 usage、charges 或消耗方式。

### AI

- AC-CMB-060：AI 战斗动作只能基于自身状态、可见状态和已知/推测信息，不得读取玩家隐藏真值。
- AC-CMB-061：AI 道具组合必须通过能力/战术包评分驱动，不得继续只靠新增 item id 特例。
- AC-CMB-062：敌人拾取目标必须按价值、距离、风险和构筑缺口评分，不得永远选择最近节点。

### UI And Text

- AC-CMB-080：拾取卡、背包、日志和情报悬浮主文案必须走玩家文案层，不得直接显示 rulesDescription 或 counterplay。
- AC-CMB-081：已知敌方道具详情可显示 `uiEnemyCounter`，但必须写成玩家可执行应对，不显示设计审查语气。
- AC-CMB-082：主动/被动效果条必须显示当前生效效果、剩余回合和目标，而不是只显示通用道具介绍。

### Tutorial

- AC-CMB-090：选择需要新手教程后，正式开局四选一必须延后到脚本化训练场景完成或跳过后。
- AC-CMB-091：教程场景必须生成 2 名属性总值为 10 的固定教学敌人，且位于玩家 5 格内。
- AC-CMB-092：教学敌人必须使用固定动作脚本和固定攻击方向，不读取普通 AI 权重。
- AC-CMB-093：第一名教学敌人必须让玩家实际完成防御读情报、方向闪避、3 点优势投入速度、进攻击杀。
- AC-CMB-094：第二名教学敌人必须让玩家实际完成基于低智力情报的优势支付说服。
- AC-CMB-095：教程检查点恢复、教学装备和非正式伤害不得影响正式开局。

### QA Traceability

- AC-CMB-100：战斗相关测试必须引用本文件 AC 编号或规则书对应章节。
- AC-CMB-101：新增战斗公式、动作矩阵、AI 行为、道具文案变更必须有自动化测试或登记测试债务。
